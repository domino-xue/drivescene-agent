# Agent Evaluation

DriveScene Agent separates planner quality, completion judgment, and deterministic runtime
module tests. A perfect regression score is not presented as open-domain model accuracy.

## Stratified planner benchmark

`evals/agent_planner_cases_200.jsonl` is the primary planner benchmark. It is generated by
`scripts/build_planner_eval_dataset.py`, validated before every run, and accompanied by a
SHA-256 manifest.

| Split | Cases | Intended use |
| --- | ---: | --- |
| development | 40 | Prompt and tool-contract development; never a headline score |
| regression | 40 | Known capability and failure-mode regression |
| heldout | 60 | Primary natural-language generalization result |
| adversarial | 40 | Mixed Chinese/English, distractors, negation, and exact-field traps |
| safety | 20 | Destructive-operation recall and safe-operation false-positive checks |

The 200 cases cover retrieval, evidence lookup, raw analysis, artifact workflows, table
transforms, and safety. Each case stores `split`, `category`, `difficulty`,
`template_family`, and capability `tags`. The validator rejects duplicate ids/questions,
missing expectations, invalid split labels, and template-family overlap across splits.

The legacy 30-case file is retained only to reproduce historical results. New claims should
use the 200-case benchmark and report heldout, adversarial, and safety splits separately.

Build and validate the dataset:

```powershell
& 'D:\app\envs\agent\python.exe' scripts\build_planner_eval_dataset.py
```

## Planner metrics

A whole case passes only when all applicable checks pass:

- bounded step count;
- registered tools only;
- ordered dependencies;
- required and forbidden tool selection;
- recursive argument-subset checks;
- correct confirmation behavior.

Reports include whole-case pass rate, per-check accuracy, category/split/difficulty results,
failed case ids, and 95% Wilson confidence intervals. Do not call this metric model
"accuracy" without the `whole-case` qualifier.

Run the configured planner on primary splits:

```powershell
& 'D:\app\envs\agent\python.exe' scripts\evaluate_agent.py `
  --suite planner `
  --splits heldout,adversarial,safety `
  --output outputs/planner_primary_results.json
```

Run the deterministic heuristic fallback on all 200 cases:

```powershell
& 'D:\app\envs\agent\python.exe' scripts\evaluate_agent.py `
  --suite planner `
  --use-heuristic-planner `
  --output outputs/planner_200_heuristic_results.json
```

The current heuristic fallback passes 18/200 cases (9.0%, Wilson 95% CI 5.8%-13.8%).
This is an intentionally narrow offline baseline, not the production planner.

## Planner prompt ablation

`scripts/run_planner_ablation.py` runs the same selected cases through controlled variants:

| Variant | Rich tool contract | Schema correction retry |
| --- | --- | --- |
| `full` | yes | one bounded retry |
| `no_retry` | yes | no |
| `schema_only` | names, purpose, and argument schema only | one bounded retry |
| `names_only` | tool names only | one bounded retry |
| `heuristic` | not applicable | not applicable |

The runner records the model and temperature, git commit, dataset SHA-256, selected splits,
per-case output, Wilson intervals, and percentage-point deltas against `full`.

```powershell
$env:OPENAI_API_KEY = '<your-key>'
& 'D:\app\envs\agent\python.exe' scripts\run_planner_ablation.py `
  --variants full,no_retry,schema_only,names_only,heuristic `
  --splits heldout,adversarial,safety `
  --workers 8 `
  --request-timeout 180 `
  --output outputs/planner_ablation_results_deepseek_v4_flash.json
```

Do not compare variants produced by different model versions, temperatures, dataset hashes,
or split selections.

### Validated DeepSeek V4 Flash result (2026-08-30)

The completed run used `deepseek-v4-flash`, temperature 0, reasoning effort `xhigh`
(mapped by the provider to `high`), and the 120 primary cases from the heldout,
adversarial, and safety splits. The dataset SHA-256 was
`9629d1c02fd189452fcff0dd3690a887653fd4aa729d3a480cdcf41d875ac1d5`.

| Variant | Whole-case pass | Wilson 95% CI | Delta vs full |
| --- | ---: | ---: | ---: |
| `full` | 104/120 (86.7%) | 79.4%-91.6% | - |
| `no_retry` | 102/120 (85.0%) | 77.5%-90.3% | -1.7 pp |
| `schema_only` | 26/120 (21.7%) | 15.2%-29.9% | -65.0 pp |
| `names_only` | 0/120 (0.0%) | 0.0%-3.1% | -86.7 pp |
| `heuristic` | 9/120 (7.5%) | 4.0%-13.6% | -79.2 pp |

All variants contain the same 120 unique case ids. Paired exact McNemar tests against
`full` give p=0.6875 for `no_retry`, p<1e-23 for `schema_only`, p<1e-31 for
`names_only`, and p<1e-28 for `heuristic`. Therefore, this run supports the contribution
of rich tool contracts but does not establish a statistically reliable retry benefit.

The full planner scores 92.5% on adversarial, 83.3% on heldout, and 85.0% on safety
cases. Its main remaining weakness is the table category at 6/13 (46.2%); argument
matching accounts for 15 of the 16 failed full-planner cases. These limitations must remain
visible when the aggregate score is cited.

The tracked compact result is
`evals/planner_ablation_deepseek_v4_flash_summary.json`; the ignored full per-case artifact
is `outputs/planner_ablation_results_deepseek_v4_flash.json`.

## Deterministic runtime ablation

`scripts/run_runtime_ablation.py` isolates three non-model runtime modules using targeted
failure-mode cases. These numbers demonstrate module behavior, not open-domain generalization.

| Module | Full runtime | Module removed | Delta |
| --- | ---: | ---: | ---: |
| Typed Blackboard argument binding | 20/20 valid handoffs | 0/20 | +100.0 pp |
| Task-completion evaluator | 13/13 correct statuses | 8/13 | +38.5 pp |
| Risk gate confirmation classification | 24/24 | 12/24 | +50.0 pp |

The risk-gate ablation also changes destructive-operation recall from 100% to 0% when the
gate is removed. Since these are balanced, constructed cases derived from module contracts,
use them as mechanism evidence rather than a broad accuracy claim.

```powershell
& 'D:\app\envs\agent\python.exe' scripts\run_runtime_ablation.py `
  --output outputs/runtime_ablation_results.json
```

## Task-completion evaluator

`evals/agent_evaluator_cases.jsonl` contains 13 deterministic completion, cancellation, and
replan cases. The cases distinguish tool success from actual task completion: for example,
creating an export directory without copying requested evidence must still return
`needs_replan`.

```powershell
& 'D:\app\envs\agent\python.exe' scripts\evaluate_agent.py `
  --suite evaluator `
  --output outputs/agent_evaluator_results.json
```

## Reporting rules

- Always state the number of cases and evaluated splits.
- Use percentage points for absolute rate changes.
- Keep development and regression results separate from heldout results.
- Report the dataset hash, model, temperature, and code revision for model comparisons.
- Treat the 200 cases as a finite contract benchmark, not proof of arbitrary user-query
  generalization.
- Describe 100% targeted-module results with their constructed-case scope and denominator.
